# Помощник прораба

Telegram-бот для мастера на стройке. Мастер пишет дневной отчёт обычным текстом (для голоса есть
диктовка Telegram). Бот находит работы и объёмы, сопоставляет их с позициями сметы и показывает черновик.
После подтверждения бот записывает объёмы в Google-таблицу (столбец нужной даты) и в Битрикс24
(элементы смарт-процесса).

- Если позиция не найдена или подходит несколько, бот спрашивает, а не угадывает.
- До записи строку можно изменить, удалить или добавить кнопками. Записанное за день тоже можно исправить.
- Если объём больше остатка по смете, бот предупреждает.
- Бот отвечает на вопрос вроде «сколько осталось по кабелю 3х2,5?».
- После записи бот даёт ссылку на таблицу.

## Как это устроено

Каждое сообщение мастера — один ход агента: `codex exec` с моделью DeepSeek. Агент читает инструкцию
(`src/engine/workdir/AGENTS.md`), вызывает инструменты MCP (`python -m src.mcp`) и заканчивает ход одним
результатом: черновик, вопрос, ответ или ошибка.

- **Сопоставление.** Справочник позиций читается из таблицы. Python нормализует текст (числа словами,
  «3 на 2,5» → «3х2,5», «6-ка» → диаметр из справочника) и находит кандидатов нечётким поиском. Агент
  выбирает среди кандидатов. Если лучшие кандидаты близки, позиция считается спорной, и бот задаёт вопрос.
- **Точная часть — в Python.** Единицы измерения, остатки, проверка черновика и все записи. LLM не считает
  числа и ничего не пишет в хранилища.
- **Если LLM ошиблась.** Мастер видит черновик до записи и исправляет его кнопками. Запись идёт только после
  кнопки «✅ Записать». Повторная запись за тот же день и позицию заменяет значение, а не дублирует его.
- **Сбои.** Сначала пишется таблица, потом Битрикс24. Если что-то не записалось, бот сообщает и даёт кнопку
  повтора.
- **Ограничения.** Голосовые сообщения не распознаются (используйте диктовку Telegram). Ход агента занимает
  10–15 секунд.

## Запуск

Нужны Python 3.12, Node.js 22 и `codex`:

```bash
npm install -g @openai/codex
python3 -m venv .venv && . .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env    # заполните значения
python -m src.bot
```

Docker:

```bash
cp .env.example .env
docker compose up --build
```

Ключ Google для Docker кладётся в `secrets/google_service_account.json`.

## Настройка `.env`

Без Google и Битрикс24 бот работает на тестовых данных (`SHEETS_BACKEND=fixture`, `CRM_BACKEND=fake`).
Обязательные значения:

| Переменная | Что это |
|------------|---------|
| `TELEGRAM_BOT_TOKEN` | Токен бота от @BotFather |
| `TELEGRAM_ALLOWED_CHAT_IDS` | Id чатов, которым можно пользоваться ботом (через запятую) |
| `DEEPSEEK_API_KEY` | Ключ DeepSeek API |

Для настоящих хранилищ:

| Переменная | Что это |
|------------|---------|
| `SHEETS_BACKEND=google` | Включить Google Sheets |
| `GOOGLE_SERVICE_ACCOUNT_FILE` | Путь к JSON-ключу сервисного аккаунта (у аккаунта право «Редактор» на таблицу) |
| `GOOGLE_SHEET_ID` | Id таблицы из её адреса. Одна вкладка — один объект |
| `CRM_BACKEND=bitrix` | Включить Битрикс24 |
| `BITRIX_WEBHOOK_URL` | Входящий вебхук с правами `crm` и `userfieldconfig` |

Остальные переменные описаны в `.env.example`.

Подготовка хранилищ:

```bash
python -m src.tools.seed_test_sheet --site Садик --site Школа   # заполнить таблицу по образцу
python -m src.tools.bitrix_setup --site Садик --site Школа      # создать смарт-процесс в Битрикс24
```

## Команды бота

`/start`, `/help`, `/today` — записанное за сегодня, `/day 02.11` — за другой день, `/site` — выбрать объект,
`/sheet` — ссылка на таблицу.
